riv — 分布式版本控制系统

v0.2.0 · Rust · MIT OR Apache-2.0

Linux ✓ macOS ✓ Windows ✓ Termux / Android ✓ rust-version ≥ 1.85 自有格式 · 不兼容 git

riv 是一个用 Rust 编写的分布式版本控制系统。它实现了与 git 等价的核心工作流 （init / add / commit / status / log / branch / checkout / diff），但采用 完全自有的存储格式——不与 git 互操作，也不背负 git 的历史包袱。

riv 的定位是「实际生产力工具」：大文件友好、并行哈希、增量 diff， 并且一套代码在 Windows / Linux / macOS / Termux 上行为完全一致—— 三平台均从源码直接编译，无需任何预编译产物。

01riv 是什么

如果你熟悉 git，可以把 riv 理解为「git 核心工作流的极简再实现」：

维度riv 的选择
存储格式自有二进制对象格式（RIVOBJ 帧 + blake3 内容寻址 + zstd 压缩），不读取也不写入 .git
哈希算法blake3（并行、快）
diff 算法Myers O(ND) 线性空间分治，输出对齐 git 的 unified diff
忽略规则.rivignore，语法与 .gitignore 相同
分支模型轻量分支（纯引用文件）+ 第一父提交历史
平台支持Windows / Linux / macOS / Termux，同一份源码、同一种构建命令

三平台，一种体验

riv 在以下平台使用完全相同的源码和构建命令（cargo build --release）， 并对平台差异做了显式对齐，保证行为一致：

  • 路径分隔符：Windows 的 \ 与 verbatim 路径（\\?\C:\...）在入口统一归一化，仓库内路径一律以 / 表示；
  • 执行位：Windows 无 exec 位，riv 显式忽略它（对齐 git core.filemode=false），避免 Linux 提交的文件在 Windows 上永远显示 modified；
  • 符号链接：Windows 上回退为普通文件（对齐 git core.symlinks=false）；Unix / Termux 完整支持；
  • 编辑器回退：commit 无 -m 且无 $EDITOR 时，Unix 回退 vi、Windows 回退 notepad；非交互环境明确报错而非挂起。

02安装与构建

riv 不提供预编译二进制——所有平台统一从源码编译，保证你拿到的就是这份代码本身。 唯一的前置条件是 Rust 工具链（rust-version ≥ 1.85，推荐使用 rustup 安装稳定版即可）。

Linux / macOS

# 1. 安装 Rust（如已安装可跳过）
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
source "$HOME/.cargo/env"

# 2. 解压源码包并进入目录
tar xzf riv-0.2.0.tar.gz
cd riv-0.2.0

# 3. 编译 release 版本
cargo build --release

# 4. 产物位置（可加入 PATH 或软链到 ~/.local/bin）
./target/release/riv --help

Windows

Windows 上推荐两种工具链之一，任选其一即可，构建命令完全相同：

方案 A：GNU 工具链（MinGW-w64）

适合不想装 VS 的场景

  1. 安装 rustup：下载并运行 rustup-init.exe
  2. 安装 MinGW-w64（或通过 MSYS2：pacman -S mingw-w64-ucrt-x86_64-gcc），确保 gcc 在 PATH 中
  3. 设置默认工具链：rustup default stable-gnu

方案 B：MSVC 工具链

官方默认，需 VS 生成工具

  1. 安装 rustup（默认即为 stable-msvc）
  2. 安装 VS Build Tools，勾选「使用 C++ 的桌面开发」
  3. 在「x64 Native Tools 命令提示符」或普通终端中均可直接构建
# 在 PowerShell / CMD 中（任选上述一种工具链后）
tar xzf riv-0.2.0.tar.gz
cd riv-0.2.0

cargo build --release

:: 产物：target\release\riv.exe
.\target\release\riv.exe --help
路径分隔符已在内核层处理：Windows 上 riv add .\src、riv add ./src、riv add src 等价，仓库内路径一律以 / 显示；\\?\C:\... verbatim 路径同样正确解析。

Termux (Android)

Termux 是 Android 上的完整 Linux 环境，riv 可直接在 Termux 中编译运行，无需 root：

# 1. 安装 Rust 与 C 工具链（clang 为依赖 crate 所需）
pkg update
pkg install rust clang

# 2. 解压源码包（如从其他设备拷贝，放在 $HOME 下，勿放 /sdcard——FAT 无 exec 位）
tar xzf riv-0.2.0.tar.gz
cd riv-0.2.0

# 3. 编译（Termux 的 $HOME 位于 ext4/f2fs，exec 位与符号链接均可用，走完整 Unix 语义）
cargo build --release

./target/release/riv --help
注意：请将仓库放在 $HOME（如 ~/projects），不要放在 /sdcard。 共享存储多为 FAT/exFAT，没有 Unix 权限位，riv 的文件模式语义会退化为 git 的 core.filemode=false 行为（这是有意为之的安全兜底，不影响仓库正确性）。

构建验证（可选）

cargo fmt --all --check          # 格式干净
cargo clippy --all-targets       # 零警告
cargo test                       # 167 个测试全部通过

03快速开始

# 初始化一个仓库（创建 .riv/ 目录）
$ riv init

# 创建一些文件并暂存
$ printf 'hello\n' > a.txt
$ riv add .

# 查看状态（两列模型 + untracked）
$ riv status
A  a.txt

# 提交
$ riv commit -m "first commit"
[main 1a2b3c4d] first commit

# 历史
$ riv log --oneline
1a2b3c4d first commit

# 分支与切换
$ riv branch feature
$ riv checkout feature

# 查看差异
$ riv diff --stat

完整命令演示可运行包内脚本（Linux/macOS/Termux）：

./demo.sh ./target/release/riv

05Token 管理（riv auth）

riv 连接远程时需要身份凭证。riv auth 是 riv 的「token 保险柜」， 按优先级从高到低读取：

优先级来源适用场景
1环境变量 RIV_TOKENCI/CD 与临时覆盖：不落盘、用即焚
2系统钥匙串Windows 凭据管理器 / macOS 钥匙串 / Linux Secret Service
3本地文件 ~/.config/riv/credentialsTermux 等无 DBus 的环境（Unix 权限 600）

登录

$ riv auth login
Token for github.com (input hidden): # 输入时屏幕不回显
Token for github.com saved to system keyring.

在 Termux 等没有钥匙串的环境会自动降级到本地文件：

$ riv auth login
Token for github.com (from stdin):
System keyring unavailable; token for github.com saved to ~/.config/riv/credentials (mode 600).

查看状态

$ riv auth status
Token status for github.com:
  environment variable RIV_TOKEN       not set
  system keyring                       set (ghp_****wxyz)
  credentials file (~/.config/riv/credentials) not set

Effective token: ghp_****wxyz (from system keyring)

token 一律脱敏展示（保留前 4 后 4 个字符）；日志与错误输出中的 Authorization 头同样打码。

清除

$ riv auth logout
Removed token for github.com from: system keyring.

环境变量属于父 shell，riv 无权清除，logout 会提示你手动 unset RIV_TOKEN。

CI/CD 用法

# GitHub Actions：优先读环境变量，不落盘
- name: Push with riv
  env:
    RIV_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: riv push origin main

自定义主机

默认主机为 GitHub 预设（https://github.com），可用 RIV_BASE_URL 环境变量或 --host 参数覆盖，指向任意 riv 远程（结构通用，不绑死 GitHub）：

$ riv auth login --host https://git.example.com:8443
$ riv auth status --host git.example.com:8443

06.rivignore

.rivignore 的语法与 .gitignore 完全相同（底层使用 Rust 生态的 ignore crate，gitignore 规范第 2 版）：

# 忽略编译产物
/target
**/*.rs.bk

# 忽略日志但保留 logs 目录本身
*.log
!logs/.gitkeep

# 忽略操作系统垃圾
.DS_Store
Thumbs.db
  • 支持仓库根的 .rivignore 与各子目录的局部规则；
  • 被忽略文件的变更不会出现在 status / add 中；
  • 需要强制添加时使用 riv add -f <path>；
  • .riv/ 目录自身永远被忽略，无需配置。

07跨平台一致性设计

「同一份源码、同一种构建命令、同一种体验」不是口号，而是逐项对齐的结果。以下是 riv 处理过的关键平台差异：

1. 路径分隔符与 Windows verbatim 路径

Windows 的路径分隔符是 \，且标准库的 fs::canonicalize 会返回 \\?\C:\... 形式的 verbatim（扩展长度）路径。riv 在仓库入口处统一做两件事：

  • 把用户输入与 current_dir() 拼成绝对路径后，做组件级归一化（剥除 verbatim 前缀时必须按路径组件重建，不能按字符串剥离）；
  • 输出到索引、树对象、status、diff 的路径一律以 / 连接。

效果：riv add .\src、riv add src、riv add ./src 在三个平台行为完全一致， Windows 上也不会出现 OutsideRepo 误判。

2. 执行位（exec bit）

Unix 用 mode 的最高三位区分普通文件与可执行文件；Windows 没有执行位，file_mode 永远只返回普通文件。 若逐位比较，Linux 提交的可执行脚本在 Windows 上会被永久判为 modified。riv 的对齐策略（对齐 git core.filemode=false）：

  • Unix：完整模式语义（普通 / 可执行 / 符号链接）；
  • Windows：比较时屏蔽 exec 位（(a & !0o111) == (b & !0o111)），杜绝幻影变更。

3. 符号链接

Unix / Termux（$HOME 在 ext4/f2fs）完整支持符号链接的创建、检出与变更检测； Windows 上回退为普通文件（对齐 git core.symlinks=false），不会报错，只是语义降级。

4. 编辑器与 TTY

commit 不带 -m 时回退 $EDITOR / $VISUAL； 两者都未设置时：Unix 回退 vi，Windows 回退 notepad。 若 stdin 不是终端（如 CI、管道），明确报错并提示使用 -m / -F，绝不挂起。

5. Token 存储

riv auth 的三级存储在各类平台上都可用，只是后端不同：

  • 环境变量：RIV_TOKEN 全平台一致，优先级最高（CI 首选）；
  • 系统钥匙串：macOS Keychain、Windows 凭据管理器、Linux Secret Service（经 DBus）；
  • 文件回退：无 DBus 的环境（如 Termux、极简桌面）钥匙串不可用时自动降级到 ~/.config/riv/credentials（chmod 600），流程不中断、不报错。

08内部原理

对象模型

所有内容寻址对象共享一个二进制帧：

RIVOBJ\x01\x00 | type(u8) | payload_len(u64 LE) | payload
  • type：1 = blob，2 = tree，3 = commit；
  • 对象 id = blake3(完整序列化字节)，即对头部 + 内容整体哈希；
  • payload 经 zstd 压缩后按 fan-out 目录（前 2 字节）存放，tmp + rename 原子写入。

索引与 racy 检查

索引（.riv/index）记录每个路径的 oid / mode / size / mtime_sec / mtime_nsec。 status 与 add 依赖 stat 缓存避免重复读文件；当文件 mtime 秒 ≥ 索引文件自身 mtime 秒时 （粗粒度时间戳文件系统上的经典竞态），强制重新哈希——与 git 的 racy-clean 检查一致。

diff：对齐 git xdiff 的 Myers 算法

riv-diff 实现了 Myers O(ND) 的线性空间分治版本，与 git 的 xdiff 同构：

  • 每层递归先剥离公共前后缀，空维直接返回；
  • 前向 / 后向搜索边界首次重叠时的空蛇作为分裂点；
  • 进度保证：剥离后 D ≥ 2，递归必然收敛；
  • 成本安全阀 max(256, sqrt(n+m))：差异极大时退化为合法但非最小的编辑脚本（与 git 的 mxcost 行为一致）。

输出为 git 风格 unified diff（--- a/x / +++ b/x / @@ hunk），hunk 内稳定遵循「先删后增」。

性能取向

  • 并行哈希：add 用 rayon 并行处理文件，大文件（≥ 1MB）走 mmap 零拷贝；
  • 流式写入：blob 经 zstd Encoder 边算边写，内存占用与文件大小无关；
  • 增量 status：只重算 stat 缓存失效的路径。

项目结构

crates/
  riv-diff/    Myers O(ND) 线性空间 diff（零依赖，可独立使用）
  riv-core/    对象库、索引、引用、快照、状态、检出、日志、分支、凭证
  riv-cli/     clap 命令行界面

09FAQ

riv 和 git 是什么关系？能读 .git 仓库吗？

没有关系，也不能。riv 使用完全自有的存储格式（.riv/ 目录、RIVOBJ 对象帧、blake3 哈希）， 既不读取也不写入 git 的任何文件。你可以理解为「同一工作流哲学的另一个实现」。

为什么压缩包里没有可执行文件？

riv 以「代码本身可移植」为分发原则：Windows / Linux / macOS / Termux 使用同一份源码、 同一条命令 cargo build --release 构建。这样每个平台拿到的都是针对本机优化的产物， 也避免预编译二进制被质疑「只是打包好的东西支持」。

Windows 上 riv add .\src 能用吗？

能。反斜杠、正斜杠、相对路径、绝对路径、verbatim 路径（\\?\C:\...）在入口全部归一化， 行为与 Linux 一致。这是内核层的修复，不是 CLI 层的补丁。

为什么 Windows 上可执行文件的状态不显示 modified？

这是有意对齐 git core.filemode=false：Windows 没有执行位，逐位比较会把 Linux 提交的 可执行文件永久判为脏。riv 在非 Unix 平台上显式忽略 exec 位。

Termux 里编译要装什么？

pkg install rust clang，然后 cargo build --release。注意仓库放在 $HOME （ext4/f2fs，有完整权限位），不要放 /sdcard（FAT/exFAT 无权限位）。

支持远程仓库吗？

0.2.0 已内置 token 凭证管理层（riv auth login/status/logout，环境变量 > 系统钥匙串 > 本地文件三级存储），远程协议本身（fetch/push/pull）在路线图上，见下节。

riv 的文件都存在哪里？

  • 对象库：.riv/objects/（zstd 压缩 + fan-out 目录，tmp+rename 原子写入）；
  • 索引：.riv/index；
  • 引用与 HEAD：.riv/refs/、.riv/HEAD；
  • 配置：.riv/config。

卸载 riv = 删除二进制 + 删除项目里的 .riv/ 目录，不留任何全局状态。
